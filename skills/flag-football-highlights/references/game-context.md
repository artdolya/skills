# Private game context

Use this structure when preserving game-specific human corrections, preferences, and project continuation details. Store the populated record in the private football workspace, for example `<game-folder>/review/game-context.md`, alongside the current roster and event ledger. Adapt an existing equivalent record rather than creating a competing source of truth. This package contains the structure only, not a real team's history.

## Game facts and people

- Game ID, team and season, opponent, date, location, stage, and the original source for each fact. Keep unknown values explicit.
- Shared roster reference and the current game's attendance, aliases, jersey assignments, and uniform exceptions. Record a corrected number as a superseding observation while preserving the earlier history; tentative mappings remain qualified.
- Confirmed halftime boundary, first-half narrative, halftime score, and final result, each with evidence. Separate official results from suspicions about missing or unrecorded plays.
- Actual participants in cover/team images, with image or source interval. Distinguish attendance at the game from attendance at a later celebration and from who appears in a photograph.

## Corrections and requested moments

For each correction, keep the original human text and retrievable source/message reference, game/event ID, exact source filename and interval, and the native timeline version/item corresponding to any user timestamp. Record the earlier interpretation, corrected actor/action/outcome, role distinctions, and affected banner/replay decisions. Keep genuine conflicts visible.

Index user-requested episodes in the event ledger before placement. Retain meaningful attempts, support, reactions, and humor; a near miss must not become a completed catch or interception. A setup moment cannot inherit a later interception, and a flag pulled from a receiver who did not catch the ball cannot become a stopped completed reception. Check existing native clips before adding a requested episode again. An old edited timestamp is a versioned lookup hint, not a durable source anchor.

## Preferences and approvals

Record the requested emotional framing, vocal/instrumental preference, music style references, supplied/licensed assets, explicit replay choices, accepted edits, and user deletions. Preserve the precise scope of any spending approval. A stated intent to buy a song does not establish purchase; approval of a music edit does not approve a cover, publication, or another paid operation. A question about an award does not authorize adding it.

## Resume and verify

- Keep the actual ChatCut project reference, timeline ID, last verified version, frame rate/resolution, and date of verification in this private record. Re-read current native state before relying on the snapshot.
- List current plans, review records, source/media inventory, cover outputs, and their locations relative to the verified football workspace. Identify superseded artifacts and stale scripts so later sessions do not replay obsolete edits.
- Record native implementation separately from planned work, plus coverage, attribution, and delivery gaps. A prior successful export or project link does not prove current media access or that the correct project is open.

Use the [review contract](review-contract.md) for the event ledger and coverage details. Keep personal names, media, project identifiers, and original correction history in the private workspace; synchronize that workspace separately when needed on another device.
